## 1. What the product is (60 seconds)

An **AI investment analyst that obeys written rules**. A user picks (or configures) an
*investor policy* — e.g. "Conservative: max 2% per trade, act only when 75% sure." A team of
AI agents then analyses stocks and produces **decision cards** (buy/sell/wait + size + reasons),
every card is checked by a rule-based **safety engine** that can VETO it, and everything is
recorded in a **decision log**.

**The demo money-shot** (design everything around this): two panels, same stock, same day —
the Aggressive policy **BUYs 6.4%**, the Conservative policy **WAITs**. Same evidence,
different rules, different behaviour, with the "why" one click away. That contrast is the product.

**Trust is the brand.** Unlike every other "AI trading" app, we can show: the veto log
(the AI being stopped by hard rules), the full "why" of every decision, and an adherence
badge ("0 policy violations this month"). Make trust visible everywhere.

## 3. Schema: DecisionCard (one line of the JSONL)

| Field | Type | Meaning / how to render |
|---|---|---|
| `decision_id` | str | unique id — your React key / detail-page URL |
| `ts` | float | unix seconds — render local time |
| `ticker` | str | `"NVDA"`, `"RELIANCE.NS"` (`.NS` = Indian stock) |
| `action` | str | `BUY` / `SELL` / `HOLD` / `WAIT` — big badge (green/red/grey) |
| `position_size_pct` | float | % of portfolio to invest (0 for WAIT) |
| `stop_loss_pct` | float | auto-exit if it drops this % |
| `take_profit_pct` | float | target profit % |
| `confidence` | float 0–1 | stated confidence — meter/donut; show as % |
| `policy_name` | str | which rulebook decided — colored chip per policy |
| `reasoning` | str | one-line explanation — display as text, **never parse it** |
| `evidence` | list | the "why" — see EvidenceItem below; expandable panel |
| `policy_clauses_applied` | list[str] | which rules were binding — chips in the detail view |
| `evidence_cost_spent` | float | how much analysis effort was used (vs policy budget) |
| `risk_verdict` | str | `APPROVED` / `VETOED` / `PENDING` — the trust centerpiece |
| `risk_reasons` | list[str] | human-readable pass/veto reasons — always show on VETOED |
| `schema_version` | str | render `"1.0"`; if unknown version, degrade gracefully |

**EvidenceItem** (entries of `evidence`): `tool` (who found it), `kind`
(technical/news/fundamental/macro), `summary` (one line), `direction`
(−1 bearish … +1 bullish — tiny diverging bar), `confidence` (0–1), `reliability`
(0–1 source quality), `ts`, `cost_units`.

**Policy JSON** (the rulebook; render read-only first, editor later): `policy_name`,
`objective`, `horizon`, `max_position_pct`, `max_daily_loss_pct`, `max_open_positions`,
`stop_loss_pct`, `take_profit_pct`, `confidence_to_act`, `tool_priorities` (ordered),
`forbidden_evidence`, `evidence_budget`.

## 4. Pages (build in this order)

1. **Decisions feed** — reverse-chronological cards: ticker, action badge, size, confidence
   meter, policy chip, verdict stamp. Filters: policy, verdict, ticker. Click → detail.
2. **Decision detail ("Why?")** — the signature page: full card + evidence list (per-item
   direction bars, reliability), policy clauses applied, cost used vs budget, and for VETOED
   a prominent red box quoting `risk_reasons`.
3. **Compare view** — two policies side-by-side for the same ticker/moment (the money-shot).
   Data: two cards sharing `ticker` with different `policy_name` (see the NVDA pair in sample).
4. **Veto log** — only VETOED cards. Tagline: *"Where the safety rules said no."*
5. **Portfolio** — equity curve, cash, positions table, daily P&L (portfolio_sample.json).
6. **Policies** — the four rulebooks rendered human-friendly; later: questionnaire →
   generate a custom policy JSON (product feature, post-October).
7. **Adherence badge** (later, data from Malhar's scorer): "N decisions, 0 violations this month."

## 6. Rules (break these and things burn)

1. **Never** compute or alter a decision client-side — you render what the log says.
2. **Never** parse `reasoning`/`summary` strings for data — structured fields only.
3. Unknown `schema_version` → render what you recognise + a "partial data" notice, never crash.
4. VETOED is not an error state — it's the product working. Style it as protection, not failure.
5. Money/percent formatting: two decimals, explicit sign for P&L, ₹/$ by ticker suffix (`.NS` → ₹).

## 7. Design language (suggestion, your call)

Confidence = neutral blues; BUY green / SELL red / WAIT grey; VETO = amber-red shield motif.
Everything explainable in one tap: any number on screen should answer "says who?" via the
evidence panel. Boring-trustworthy beats flashy-crypto. Dark mode from day one if it's cheap.
